# ADR 0007: инструменты и границы синтетического каркаса

Дата: 7 октября 2026 года. Статус: **предложено для ревью #19**; реализованный технический выбор, не новое подтверждение пользователя. Go/PostgreSQL/chi и контракт #16 уже приняты — ADR 0004/0006 и DECISIONS. Решение проверяется вместе с PR каркаса.

## Контекст и выбор

Нужен воспроизводимый локальный запуск web/API/БД до предметных схем, auth и CI. Выбраны Go 1.27.1, chi 5.3.2, pgx 5.11.0 (database/sql stdlib), goose 3.28.0, PostgreSQL 18.3; Node 24.19.0/npm 11.9.0, React/React DOM 19.3.0, TypeScript 5.9.3, Vite 8.3.3. Версии из доступных metadata и реально собранных пакетов; PostgreSQL выбран из существующего проверенного официального образа. Docker stages и PostgreSQL закреплены digest, npm — lockfiles, Go — go.mod/go.sum. Требование Vite Node ^20.19 или ≥22.12 выполняется; pgx/goose/chi собраны выбранным Go. Пакеты API-инструментов сохранены из #16; Swagger UI 5.33.1.

Go обслуживает `/`, web-assets, служебные операции и runtime Swagger на одном origin. Vite dev proxy повторяет этот origin-подход без CORS. Небольшая web-оболочка на существующих токенах/локальном Rubik проверяет готовность среды; не копирует прототип коллеги #23. Бизнес-операции #16 остаются запланированы и не регистрируются даже как заглушки. Runtime OpenAPI фильтруется по x-status, chi.Walk сверяется с ним и явным списком static exceptions.

Миграции выполняет отдельный CLI с goose, без автоматического изменения БД при старте API. Goose выбран вместо собственного движка миграций; pgx stdlib позволяет использовать тот же пул для goose и readiness. API проверяет текущую версию. Синтетические fixtures изолированы в schema development; предметные Club/Account/tenant FK/RLS создаются в #20 и следующих задачах. Сам seed не доказывает безопасную изоляцию данных и не разрешает реальные данные. Compose отдельными сервисами обеспечивает порядок db → migrate → seed → api.

## Альтернативы и последствия

Самописный мигратор увеличивает обязанности по lock/версиям/транзакциям. SQL через контейнер psql без журнала не обеспечивает понятный повторный up. Тяжёлый ORM не требуется; sqlc будет оценён при появлении реальных запросов. TanStack Query/Dexie/router UI не добавляются ради одного readiness fetch; PWA/офлайн — отдельные срезы. Worker пока не имеет потребителя.

Local-only HTTP/одна dev-роль БД/sslmode=disable в Compose не предназначены для production. Разделение ролей и RLS — #20, сессии — #21, CI/HTTPS/размещение — #22. Scratch-образ работает непривилегированным пользователем и не делает внешних запросов. CA монтируется только во время network build, унаследованный proxy/TLS сохраняется. Инструкция запуска/восстановления и проверки — [ops/README.md](../../ops/README.md). Production политика хранения, RPO/RTO и реальные данные этим выбором не утверждаются.

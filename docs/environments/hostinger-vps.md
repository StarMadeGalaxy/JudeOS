Bandwidth не интерпретируется как подтверждённые TB, скорость или месячный лимит. Тип процессора/диска, регион, цена, текущая загрузка и свободное место не известны. Покупка сервера не доказывает достаточность ресурсов или доступность сервиса; нагрузку, диск и размещение образов/БД/копий проверяет #22.

Пользователь дополнительно сообщил: «К данному ip assigned domain judopride.tech, на него установлен ssl» и приложил скриншот DNS-проверки. Скриншот показывает ответы A-записи на указанный IPv4; он не содержит параметры сертификата и не подтверждает работу приложения. Попытка открыть `https://judopride.tech` через веб-инструмент этой среды не дала результата: инструмент сообщил, что URL недоступен через него. Это не доказывает недоступность VPS или ошибку SSL.

## Как может помочь Docker Manager

По [официальной инструкции Hostinger](https://www.hostinger.com/support/12040789-hostinger-docker-manager-for-vps-simplify-your-container-deployments/), прочитанной 7 октября 2026, панель поддерживает запуск Docker Compose из URL публичного репозитория или введённого YAML, просмотр контейнеров/логов/метрик, настройку портов, томов, переменных и зависимостей, доступ к терминалу. Это возможный интерфейс управления test-контуром JudeOS. Совместимость конкретного Compose, подстановка конфигурации, доступ к образам и хранение секретов в панели требуют проверки на этой VPS.

Версионированная конфигурация #22 и идентифицируемый образ должны оставаться источником развёртывания; существенные ручные изменения панели нужно отражать в конфигурации/инструкции. Секретные значения хранятся отдельно от Git и публичного Compose. Документированное Hostinger Auto-SSL относится к выбранным приложениям; автоматический HTTPS для JudeOS по одной установке Docker Manager не подтверждён. Существующий SSL сообщён отдельно пользователем; способ его обслуживания и внешний HTTPS приложения проверяются в #22.

Пароли, приватные SSH-ключи, API-токены и `.env` не отправляются в чат/Issue/PR и не коммитятся. На сервере сохраняются проверка TLS, проверка SSH host key и настроенные proxy, если они используются.

## Передача #22 и границы готовности

Площадка для удалённого test теперь предоставлена пользователем: #22 должна предусмотреть запуск JudeOS на этой VPS и проверку снаружи, чтобы серверный тест не зависел от постоянно работающего локального компьютера. Локальные проверки разработки остаются полезны; они не заменяют результат внешнего test.

Принятые #19/#20 дают приложение, миграции/seed и роли/RLS. Перед запуском #22 использует актуальную main после [PR #85](https://github.com/StarMadeGalaxy/JudeOS/pull/85), отдельный серверный test-контур и проверяет bootstrap → миграции → seed → runtime, health/readiness, внешний HTTPS и отсутствие публичного доступа к PostgreSQL. Базовый `make up` из [ops/README](../../ops/README.md) предназначен для локальной синтетической среды; его успешность не доказывает готовность публичного размещения. Обычная сборка не требует host CA; дополнительный публичный CA для HTTPS-прокси подключается явно через `BUILD_CA_PATH`, TLS verification сохраняется.

Подготовка SSH/автоматизации — [#91 и инструкция доступа](hostinger-deploy-access.md); она дополняет #22 и пока не включает приложение/release.

В рамках #88 не выполнялись вход на VPS, проверка hPanel, запуск контейнеров, настройка DNS/firewall/TLS, нагрузочные тесты или backup/restore. #22 остаётся ответственна за эти результаты в своём объёме; #88 не создаёт дублирующую задачу развёртывания или новую блокирующую зависимость. Сведения переданы в [комментарии #22 о VPS](https://github.com/StarMadeGalaxy/JudeOS/issues/22#issuecomment-6044050366) и [уточнении домена/SSL](https://github.com/StarMadeGalaxy/JudeOS/issues/22#issuecomment-6044337117).

До выполнения условий [#18](https://github.com/StarMadeGalaxy/JudeOS/issues/18)/[#24](https://github.com/StarMadeGalaxy/JudeOS/issues/24) на VPS используются только синтетические данные. Место для test не утверждает production-контур, основание обработки, права, реальные сроки хранения, SLA или готовность реального пилота.

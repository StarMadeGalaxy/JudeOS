# Планирование JudeOS / Judo Pride

Актуализировано 7 октября 2026 года по итогам критического пересмотра. Рабочие документы согласованы с архитектурой 0.4 и планом MVP 1.1. Синтетический каркас #19 реализует web/API/PostgreSQL и служебные проверки; предметные операции ещё запланированы. Планы и схемы не являются доказательством готовности MVP.

- [Исходные документы](archive/2026-10-07-inputs/README.md) — архив для сравнения, не действующая спецификация.

Точные первичные D26–D63, MVP-INTERVIEW и прежний упомянутый ADR не представлены; поля D54 и отчёты D61 требуют отдельной спецификации. Явно выписанные правила позднего приложенного плана сохранены в текущем MVP. Нумерация недоступных решений не заполнена догадками. При расхождении исторических материалов использовать текущие архитектуру/план и проверять происхождение предметного правила.

Сотрудники — первая версия. Полный MVP включает журнал, людей/семьи, допуск, поддержку и сверку, два события Telegram, офлайн текущего дня, конкретные импорты/отчёты и четыре зала. Узкий онлайн-пилот — промежуточная проверка. ЛК, чаты, нормативы/рейтинги, медицинские файлы и биллинг платформы добавляются позже.

## Принятый HTTP-стек и сопровождение

Первый онлайн-сценарий S0-01 — [API/OpenAPI и примеры](../api/README.md), [реестр](../api/ENDPOINTS.md), [словарь](../api/DATA-DICTIONARY.md) и [открытые решения](../api/OPEN-QUESTIONS.md). [ADR 0006](adr/0006-first-online-contract.md): **принят** по приёмке пользователя, PR #78 merged; семь бизнес-endpoint'ов ещё запланированы. Каркас #19 и инструменты — [ADR 0007, предложено](adr/0007-synthetic-scaffold.md), запуск — [ops/README](../ops/README.md).

Go + net/http + **chi v5**; документация всех изменяемых частей продукта и endpoint’ов обязательна. [ADR 0004, принят](adr/0004-chi-and-api-documentation.md) фиксирует выбор; [правила API/OpenAPI/Swagger UI](../docs/API-DOCUMENTATION.md) задают контракт, реестр и проверки. Исторические архивы сохраняют прежние формулировки, действующий стек определяется этим решением.

Старт любой работы по задаче требует [резервирования](../CONTRIBUTING.md#резервирование-задачи-до-начала-работы) assignee + In progress с проверкой результата. [ADR 0005, принят](adr/0005-task-claim-before-work.md) описывает повторные запросы, конкурентный старт и недоступность Projects. Статусы живут в GitHub, не в этом индексе.

При недоступности Projects API агент до работы возвращает компактный список прямых ссылок на выбранные карточки, исполнителя и просьбу установить assignee/In progress. Ждёт явного подтверждения или скриншота; после него продолжает без повторного блокера API. Для неизменившегося продолжения того же чата повторный ручной переход не требуется.

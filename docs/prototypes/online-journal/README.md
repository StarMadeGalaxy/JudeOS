# Мобильный прототип первого журнала

Issue #23. Интерактивный прототип входа → назначенного занятия → четырёх отметок. Использует [контракт первого сценария](../../../api/README.md) и [дизайн-систему](../../../DESIGN.md). Это прототип на синтетических данных с имитацией сервера в памяти вкладки, не приложение с настоящей аутентификацией/сохранением. Никакие данные не отправляются в GitHub, PostgreSQL или внешний API.

## Запуск

Из корня репозитория, Node.js 22+:

```sh
node docs/prototypes/online-journal/serve.cjs
```

Открыть http://127.0.0.1:4174. Учебный email заполнен, любой непустой пароль позволяет войти. Реальные данные не вводить. Для списка участников используются вымышленные имена. Обновление страницы очищает всю имитацию состояния. LocalStorage/cookie/IndexedDB не используются; офлайн-очереди нет.

В нижнем блоке «Прототип · синтетические данные» доступны: обычная работа, пустой список, потеря связи, потерянный ответ после записи, запрет доступа, истёкшая сессия, недоступный сервис и конфликт. Сначала открыть журнал, затем выбрать сценарий для команды. «Нет занятий» и ошибки загрузки применяются на экране списка. «Начать заново» очищает данные/сценарий и возвращает вход.

## Поведение и границы

- Четыре статуса соответствуют present/absent/sick/other. Unmarked показывается как «Не отмечен»; отсутствие не проставляется автоматически. Пробное занятие и визит — метаданные участия, не отметки.
- Выбор не становится подтверждённой отметкой до ответа адаптера. Во время ожидания кнопки этой записи заблокированы; другие участники независимы. После отказа подтверждённое значение сохраняется.
- Для неизвестного результата/503 повтора используется прежний operation_id/base_version/status; повтор не создаёт второй эффект. При потерянном ответе адаптер уже записал значение, но UI не сообщает успех до повторного ответа. Отмечено/присутствуют считаются только по подтверждённым значениям.
- При конфликте показаны текущая серверная отметка и намерение пользователя. «Оставить текущую» принимает актуальное значение. «Сохранить мой выбор» создаёт новый operation_id с актуальной base_version. Молчаливого перезаписывания нет.
- Отзыв сессии возвращает к входу; после входа имитация журнала перечитывается. Выход при неизвестном результате требует подтверждения; после входа отображается серверное состояние. Выбор клубов, восстановление пароля, финансы, создание гостей, закрытие и офлайн не входят в #23.
- Время занятия показывается в Europe/Minsk, дата фиксирована синтетическим fixture. UI не показывает UUID, технические версии и request_id в обычном потоке.

`fixture.json` соответствует SessionJournal из OpenAPI, исходная форма взята из api/examples/first-online.json и расширена шестью синтетическими участниками. app.js моделирует семантику setAttendance: UUID команды, base_version, повтор, recorded attendance. Это не HTTP-клиент: Cookie/CSRF/Origin, безопасность, 429/Retry-After, tenant/RLS и транзакции проверяются при реализации соответствующего API. Учебный вход не проверяет пароль. Кнопка «Попробовать снова» повторяет отрисовку выбранного сценария; вернуть доступность можно изменением сценария.

## Визуальные решения

Подключён существующий tokens.css без изменения глобальных токенов. Rubik 300–900 с локальными латиницей/кириллицей и font-display: swap; базовый текст 16 px. Области нажатия от 46 px, focus-visible, текстовые статусы, aria-pressed и live-status. На 320 px выбор располагается в два ряда, на desktop журнал — в две колонки. Текстовые состояния различимы без цвета.

Шрифты: @fontsource-variable/rubik **5.3.0**, пакет npm, normal Cyrillic/Latin, лицензия OFL сохранена в fonts/LICENSE. Источник: https://www.npmjs.com/package/@fontsource-variable/rubik. Внешние CDN не нужны. JP — текстовая служебная метка прототипа, не новый утверждённый логотип.

## Проверки

```sh
cd api
npm ci
cd ..
node api/node_modules/@playwright/test/cli.js test -c docs/prototypes/online-journal/playwright.config.cjs
```

Используется системный Chromium `/usr/bin/chromium`; другой путь задаётся JUDEOS_CHROMIUM_PATH. Тесты проверяют четыре отметки/поиск, сохранение после потерянного ответа, восстановление сети, явное разрешение конфликта, пустой список, отказ/истечение сессии и отсутствие горизонтальной прокрутки на 320/390/768/1280 px. Screenshot создаётся в игнорируемом dist/journal-mobile.png. Это браузерная проверка прототипа; backend/API и работа на физических iOS/Android не заявляются проверенными.

# ADR — узкий контракт настройки занятия #34

Статус: **proposed, не принят и не реализован**. Локальный проект технического решения в ветке/PR116; номер общего ADR не резервируется до согласования. [Конкретный wire и источники подтверждённых требований](SESSION-CONFIG-PROPOSAL.md). Решения владельца о ролях/состояниях не объявляются одобрением технического варианта.

## Контекст

У времени и отмены Session нет принятого wire, но существующие TrainingSession, SessionCoaches, версии/ошибки и setSessionCoaches уже определены. #34 должна завершить синтетический UI без придумывания существующих endpoint или перехвата backend #30. Владелец согласует недостающий общий контракт напрямую.

## Предлагаемый выбор

Добавить две узкие команды rescheduleSession/cancelSession с существующим TrainingSession в ответе. Для назначения сохранить setSessionCoaches и SessionCoaches, предложить необязательную reason и administrator-only права; отдельно ограничить первоначальный coach выбор в createManualSession. Основной OpenAPI/runtime до явного принятия остаются прежними.

Время и тренеры подтверждаются отдельными командами с отдельными версиями/результатами. Это уменьшает новый wire, сохраняет историю существующих назначений и делает частичный успех явным; одновременную атомарность двух секций UI обещать нельзя. После первой команды требуется чтение текущего состояния перед второй.

Ключи/результаты идемпотентности обрабатываются после текущих прав, до применимости/версии новой команды. Это позволяет получить ответ уже выполненной отмены без повторного эффекта; актуальное состояние после replay обязательно перечитывается. Серверное выравнивание этого порядка и прав не объявляется выполненным вместе с предложением.

## Альтернативы и последствия

Общая команда замены времени и coaches дала бы одну атомарную форму, но потребовала бы ещё одного request/result DTO и дублировала существующий setter. Изменение всего Session через произвольный PATCH затронуло бы неизменяемые group/venue/state/исходный ключ и усложнило права. Использование одного лишь текущего setSessionCoaches не покрывает время/отмену и не устраняет прежние manager права на сервере.

Принятие узкого wire позволяет #34 продолжить fixtures/UI параллельно будущему backend. Шаблон/генерация/SQL и применение серверных ограничений остаются #30; live интеграционная приёмка — #36. Согласование wire, готовность UI и принятие runtime — разные доказательства.

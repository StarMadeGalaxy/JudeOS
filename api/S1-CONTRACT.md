# S1: поля людей и права онлайн-журнала

Статус: **предложение для ревью #26**, не принятое изменение #16 и не реализованный API. Источник бизнес-варианта — [рекомендации агента по прямому поручению владельца](https://github.com/StarMadeGalaxy/JudeOS/issues/26#issuecomment-6060282984), 8 октября 2026. Комментарий прямо указывает, что отдельного утверждения каждого правила владельцем не было. D54 не восстановлен. Происхождение сохранено в [DECISIONS](../planning/DECISIONS.md#предложения-по-s1-и-26--8-октября-2026-года), технический вариант — [ADR 0011](../planning/adr/0011-s1-people-journal-contract.md).

## Выбор, требующий принятия

В критериях #26 без нового решения закрывает назначенный тренер. Источник предложений рекомендует **administrator/manager без назначения**, а coach-only запрещает закрытие. Здесь подготовлен этот второй вариант с явной пометкой proposed. До его принятия остаётся прежний консервативный baseline; обсуждение и этот файл не дают работающему API новых прав. В #16 HTTP-команды закрытия ещё нет. Исправление существующей отметки в closed назначенным тренером остаётся частью принятого #16.

## Поля и выдача

Точные wire-схемы и ограничения — только [OpenAPI](openapi/openapi.yaml). Требуемые бизнес-поля отличаются от обязательных технических operation_id/base_version/ID, которые нужны для повтора, ссылок и контроля конкуренции.

| Объект | Обязательные бизнес-поля предложения | Необязательные данные / ограничения | Кто получает |
|---|---|---|---|
| Person | Непустое display_name, привычное полное имя одной строкой | phone необязателен; имя не уникально, не разбирается автоматически. ID/tenant/version/автор серверные | administrator/manager своего клуба; coach только имя/ID участника журнала |
| Athlete | Существующий person_id, participation regular/guest | Account/семья/представитель/телефоны не обязательны. visit — участие в конкретном roster, не состояние Athlete | Полная AthleteProfile только administrator/manager; coach получает RosterEntry |
| GuardianLink | Конкретные представитель и Athlete, вид основания проверки и период | verified_by берёт сервер. valid_until может быть null; при наличии строго позже valid_from. Проверяют administrator/manager, без загрузки документов | Полные сведения связи только administrator/manager; выбор контакта не выдаёт кабинет |
| Основной контакт | Выбор необязателен; не более одного действующего проверенного представителя | Имя и phone (может быть null). Отзыв/истечение скрывают контакт сразу, без автоматической замены | Только разрешённый участник текущего назначенного занятия для coach; административный scope клуба |
| AdmissionSummary | Если сведения есть: admitted/not_admitted/review_required и срок | Без диагноза/файла; null — сведений нет. Недопуск не запрещает фиксировать присутствие | Минимум журнала; правила изменения/истечения дополняет #33 |
| Session / roster / Attendance | Принятые #16 ID/время/состояние/версии, четыре статуса, trial отдельно | Новые optional поля roster: primary_contact/admission/excluded. Исключённая/архивная строка сохраняет факты, без контакта/допуска | Проверка клуба, роли, текущего назначения и полей при каждом чтении |

Дата рождения в предложенном S1 отсутствует: рабочая необходимость ещё не названа. Телефон ребёнка не обязателен. Контакт/Account/Household не нужны для создания гостя. Семья, платёж, телефон и совпадение имени не создают GuardianLink или доступ. Отсутствие номера показывается явно; синтетические примеры не подставляются вместо неизвестного номера.

PrimaryContact — отдельная проекция: только display_name и phone, без Person ID представителя, списка остальных представителей, основания проверки и финансов. Нет второго контакта или fallback. Отозванная/истёкшая связь может сохраняться в административной истории, но её контакт больше не выдаётся. Сам сохранённый primary_guardian_link_id не является доказательством актуального разрешения.

## Предложенная матрица действий

Активные membership/grants и club scope обязательны; права совмещённых действующих ролей объединяются. Снятие coach не отменяет отдельную действующую роль manager/administrator. Служебная audit_reader из #20 не становится продуктовой ролью. Секреты, сессии и порядок выдачи ролей принадлежат #21.

| Действие | administrator / manager клуба | coach-only с текущим SessionCoach | coach-only после снятия |
|---|---|---|---|
| Текущий/исторический журнал, включая closed/cancelled | Да, разрешённая история клуба | Только назначенное сейчас занятие | Нет, 404 для объекта |
| Полная карточка / проверка связи / выбор контакта | Да | Нет, 403 | Нет |
| Отметить/исправить существующую активную строку planned/in_progress/closed | Да | Да | Нет |
| Закрыть planned/in_progress | Да, без назначения | Нет в предложенном варианте | Нет |
| Добавить известного / нового гостя онлайн в planned/in_progress | Да | Да, своё занятие | Нет |
| Исключить / заменить состав planned/in_progress | Да с историей | Нет | Нет |
| Изменять состав closed/cancelled | Нет | Нет | Нет |
| Новые отметки / исправление cancelled | Нет до отдельного восстановления | Нет | Нет |
| Перенос / отмена | Да с сохранением фактов, конкретные команды #29 | Нет | Нет |
| Финансы / другие представители / кабинет | Не выдаются этими операциями | Нет | Нет |

Исключение сохраняет строку и её Attendance/автора/историю, меняет excluded; физического удаления нет. Исключённая строка не разрешает новую отметку или контакт. Повторное включение исключённой строки, восстановление отменённого и массовая замена состава не проектируются скрыто: соответствующий API добавляется после отдельного правила. В closed можно исправлять существующие активные отметки, но не добавлять/исключать участников. Закрытие не меняет unmarked на absent, возвращает предупреждение и число оставшихся unmarked. Admission не блокирует фактическую отметку.

## Команды и совместимость

Девять новых операций в [реестре](ENDPOINTS.md) имеют x-status=planned, x-contract-status=proposed, x-issue=26. Расширения трёх операций #16 помечены x-s1-issue=26/proposed; источник #16 сохраняется. Ни один planned endpoint не появляется в runtime OpenAPI/chi. Миграций/обработчиков/PWA/офлайна в этом PR нет.

CreatePerson и CreateAthlete разделяют профиль и спортивное участие. Онлайн-гость атомарно создаёт Person/Athlete/roster без Account; переход в regular не меняет ID. Совпадение имени/телефона лишь кандидат на дубль. Проверенная связь использует существующий Person клуба; не создаёт аккаунта или основного контакта автоматически. Отзыв/редактирование связи, поиск/пагинация/архивирование реестра и расписание реализуются с #27/#29/#33 и отдельными контрактами; этот срез не обещает полный CRUD.

Технический proposed-вариант повторов следует инвариантам #16: operation_id уникален по tenant/actor, canonical hash включает версию API/тип/target/payload/base_version. Отсутствующий phone и null нормализуются одинаково. Остальные данные не превращаются в ключ дубля. Эффект, история и результат атомарны. Точный повтор после текущих проверок прав/состояния возвращает исходный результат и Operation-Replayed, другой payload — 409 OPERATION_ID_REUSED. После неизвестного сетевого результата повторять тот же ID/payload; после разрешения сохранённого конфликта версии — новый ID и актуальная версия. 401/403/404/невалидный ввод/актуальный запрет состояния не становятся принятым эффектом. Нет новых TTL/production-сроков: #18/#52 остаются открыты.

base_version контакта/проверки связи — Athlete.version; для close/add/guest/exclude — Session.version. Attendance.version независима. Контроль версий и изменение назначения/состояния/контакта/архива сериализуются с командой в будущей транзакции. Чужой клуб/объект проверяется раньше версии или operation_id. Неактивная связь не выдаётся повтором старого результата. Уже active roster не дублируется; повторное исключение без нового эффекта не повышает Session.version. Неподдержанная команда не переоткрывает closed/cancelled.

Общий Error/параметры/security/auth не меняются по [согласованию #21](https://github.com/StarMadeGalaxy/JudeOS/issues/21#issuecomment-6059940617). Новые конфликты используют отдельную S1CommandConflict с безопасными кодами, без контактов/оснований проверки. HTTP-политика #16: JSON до 16 KiB, строгие поля, no-store/request_id, CSRF/exact Origin для записей, нейтральные 400/401/403/404/405/413/415/429/500/503. Пути и Allow точные; общего CORS/HEAD разрешения не добавляется.

Дополнительные поля RosterEntry optional, поэтому прежние минимальные fixtures #16/#23 остаются валидны в расширенной схеме. Это не обещает, что старый строгий клиент сможет принять новые поля: UI обновляется с принятием расширения и проверяет поля/null. Новое полное AthleteProfile не подменяет минимальный DTO тренера. До принятия предложений API/UI могут изучать один wire-файл и fixtures, но не считать новые права согласованной зависимостью.

## Сценарии будущей приёмки реализации

Это требования к будущим runtime-тестам после принятия, а не результаты выполняющихся проверок безопасности.

| Сценарий | Ожидание предложенного варианта |
|---|---|
| Гость без телефона/представителя/семьи/Account | Создан онлайн с устойчивыми ID и визитом |
| Повтор гостя после потерянного ответа | Те же ID/один эффект; другое тело того же ID — 409 |
| Однофамильцы / одинаковый телефон | Не объединяются автоматически |
| Клиент задаёт DOB, tenant/автора, диагноз или документ | 400; запрещённые поля отвергаются |
| Coach открывает полную AthleteProfile | 403, без контактов/оснований проверки |
| Person/GuardianLink/Athlete чужого клуба | 404 после membership; нет межклубного FK/утечки |
| Household/плательщик без проверенной связи | Не может стать основным контактом |
| Истёкшая/отозванная связь, включая точный replay выбора | Контакт/старый результат не выдаётся; актуальная проверка, 409 при выборе |
| Нет выбранной связи / у представителя нет номера | primary_contact=null / phone=null; другой номер не выбирается |
| Два менеджера выбирают основной контакт с одной Athlete.version | Один успех, второй 409; не более одного выбора |
| Coach снят после чтения / до replay | 404; журнал/контакт/прежний результат не выдаются |
| Бывший coach имеет действующий manager | Административный доступ своего клуба сохраняется |
| Manager без SessionCoach исправляет closed | Разрешено proposed-правом, новый автор/версия/история |
| Coach-only закрывает / исключает / переносит | 403 в предложении; закрытие требует отдельного принятия выбора |
| Admin/manager закрывает с unmarked | closed, предупреждение; unmarked не становится absent |
| Добавить/исключить/заменить в closed/cancelled | 409, без частичного эффекта |
| Отметка/исправление cancelled | 409 SESSION_CANCELLED; прежние факты сохранены |
| Исключить строку с present | Строка/Attendance/автор/история сохранены, excluded=true |
| Новая отметка исключённой строки | 404; запись не возвращает её в состав |
| Admission not_admitted, участник фактически был | present сохраняется, диагнозов/файлов нет |
| Архивный участник в разрешённой истории | Факты сохраняются; новые команды/контакт недоступны |
| Две отметки / закрытие одновременно со сменой тренера | Проверки версий/назначения сериализуются; stale client не расширяет scope |
| Отозванная сессия / нет CSRF или Origin | 401 / 403, нет эффекта и replay данных |

Схемные позитивные/негативные fixtures — [s1-people-journal.json](examples/s1-people-journal.json); список девяти новых операций — [s1-operations.json](examples/s1-operations.json). `npm run check` проверяет схемы/реестр/примеры/TS; `npm run check:swagger` — отображение. Эти проверки не доказывают RLS, актуальность GuardianLink, uniqueness/конкуренцию, право закрытия или отзыв в runtime.

До интеграции #26 требуется принятая и merged #21, объединение актуальной main, сохранение auth-проверок и проверка общего контракта/counts/implemented-planned. PR101 пока открыт. Иной порядок merge согласуется отдельно; VPS release v0.1.0-test.2/schema3/checkout/manifest не меняются.

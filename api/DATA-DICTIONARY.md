# Словарь идентичности и общих инвариантов

Статус: предложение контракта [#16](https://github.com/StarMadeGalaxy/JudeOS/issues/16), [ADR 0006](../planning/adr/0006-first-online-contract.md). Источник предметной модели — [DATA-MODEL](../planning/DATA-MODEL.md) и архитектура §§3–7. Это словарь ближайшего среза, не финальная схема таблиц и не реконструкция D54. Схемы wire DTO находятся только в [OpenAPI](openapi/openapi.yaml).

| Понятие / ID | Владелец | Область и смысл | В первом HTTP-сценарии |
|---|---|---|---|
| Club / tenant_id | access | Клуб; все клубные данные изолированы этим ID. ID пути лишь кандидат до проверки membership | Разрешённые memberships, пути и Session |
| Account / account_id | access | Глобальный вход, без профилей детей; один Account может иметь несколько ролей/клубов | Метаданные входа и серверное авторство отметки |
| AuthSession | access | Серверная сессия Account, секрет в HttpOnly cookie, в БД только хеш/срок/отзыв | Security scheme; внутренний ID/хеш не выдаются |
| ClubMembership / membership_id | access | Право Account входить в клуб, со статусом/отзывом; не юридическое членство и не участие в тренировках | Только активные membership/grants |
| RoleGrant | access | Фиксированная роль, scope, период/отзыв. Scope не обходит предметный объект | administrator/manager/coach; первый сценарий требует coach + назначение |
| Person / person_id | people | Человек внутри клуба, профиль без обязательного Account. Имя не уникально; профили клубов не объединяются | Минимальный ID/имя в разрешённом roster |
| Athlete / athlete_id | people | Спортивное участие Person, устойчивый ID при переходе гостя в постоянного. Не логин и не платёжный номер | Target отметки и roster; отдельный от Person ID |
| GuardianLink | people | Проверенная связь Person-представителя с конкретным Athlete, период/основание и категории информации | Не выдаётся и не создаётся; права контактов — #26/#27/#33 |
| Household / HouseholdMember | people | Семья, состав с периодами/порядком для условий поддержки. Не разрешение представителя | Не выдаётся; подробности — S2 |
| Venue / TrainingGroup | training | Зал и организационная группа; несколько групп/тренеров, связи с периодами | Только ID/имя для выбранного занятия |
| Session / session_id | training | Конкретное занятие, устойчивое при переносе, состояние/время/версия | Список и журнал |
| SessionCoach | training | Тренеры конкретного занятия; текущее назначение проверяется при каждом запросе | Предикат scope, не список всех сотрудников |
| SessionRoster | training | Сохранённое участие Athlete на занятии; перевод группы не переписывает прошлое. Trial отдельно от participation | ID/имя/regular-guest-visit/trial; не динамический состав группы |
| Attendance | attendance | Уникально tenant/session/athlete. Независимый статус/версия, автор и время | Четыре статуса; version 0 для незаписанного unmarked |
| AttendanceChange | attendance | Неизменяемое происхождение принятой правки: до/после, автор, время, необязательная причина | Не отдельный endpoint; атомарно с отметкой |
| OperationResult / operation_id | attendance | Ключ tenant/actor/UUID, canonical hash, ответ или конфликт версии; тип/target/base_version участвуют в hash | Безопасный повтор; сроки очистки и recovery открыты |

`administrator` отображает текущую проектную роль «администратор», но защита последнего активного владельца — отдельный инвариант access, не автоматический вывод из списка ролей этого DTO. Нельзя лишить последнего владельца полномочий без передачи; конкретный механизм и контракт — #21.

## Типы и граница хранения

UUID передаются строками, не выводятся из имени/телефона/внешнего платёжного номера. Все клубные ссылки проверяются составными FK `(tenant_id, id)`; RLS USING/WITH CHECK дополняет их. Runtime не владелец таблиц, без BYPASSRLS; tenant устанавливается локально в короткой транзакции после проверки membership. Глобальные Account/AuthSession не требуют переноса профилей в access.

`version` и `base_version` — безопасные для JavaScript целые до 2^53−1, без дробей/переполнения. `Session.version` независима от версий Attendance. Дата начала фильтруется по Europe/Minsk; события хранятся как UTC, wire RFC 3339 с Z. Периоды Enrollment/назначения/семьи имеют смысл `[from,to)`, а не текущий состав на все времена; точные SQL-типы добавляются с миграциями.

Допуск не ограничивает запись факта присутствия, медицинских файлов нет. Минимальное DTO журнала пока не включает допуск/основной контакт: их поля и разрешённый доступ согласуются в #26, без придумывания D54. Отмена сохраняет отметки; закрытие не превращает unmarked в absent. Архив и исторические контакты не дают бессрочного доступа.

## Общие денежные инварианты без финансового API

Владелец финансов — contributions. Recommendation — рекомендуемая добровольная поддержка, Receipt — подтверждённое поступление, Allocation — его часть на Athlete/месяц. Плательщик не становится GuardianLink; Household не разрешает просмотр и Account не служит идентификатором ребёнка в оплате.

Деньги — целые копейки BYN, без float/конверсий. Дата поступления и месяц поддержки различаются. Отсутствие поддержки не создаёт долг и не ограничивает занятия. Для одной согласованной выборки: **чистые подтверждённые поступления = действующие распределения + нераспределённый остаток**; рекомендации не входят в равенство. Распределение и возврат блокируют Receipt, остаток неотрицателен; возврат компенсирует распределения атомарно, история не удаляется.

Внешний ID уникален только в проверенной договорной области `(tenant, provider account, external operation ID)`. Изменённый payload того же ID не игнорируется; похожие реальные оплаты без ID не схлопываются по отпечатку автоматически. Подробности/источники — модель данных §«Поддержка и поступления» и [разбор iPay](../docs/integrations/ipay/README.md); финансовый контракт — #38, актуальный профиль — #17. Публичной схемы Money/Receipt, таблиц и endpoint'ов S2 в этом контракте нет.

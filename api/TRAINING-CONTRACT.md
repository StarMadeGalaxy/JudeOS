## Состав и границы

Менеджер явно выбирает спортсменов и тренеров нового ручного занятия. Enrollment и GroupCoach, действующие на `starts_at`, служат подсказкой. Сервер сохраняет выбранный roster и SessionCoach в одной транзакции; последующие зачисления/переводы/окончания интервалов не пересчитывают уже созданные занятия, в том числе будущие. Никакой скрытой синхронизации состава группы с занятиями нет.

Срез включает справочники залов/направлений, группы, периоды зачисления/тренеров, ручное создание занятия, назначенных тренеров и чтение сохранённого roster. Принятые операции addKnownRosterAthlete/excludeRosterAthlete используются для известного спортсмена и административного исключения. Тренер только временно добавляет известного спортсмена в своё занятие; не создаёт Enrollment, не исключает, не заменяет состав. Исключение сохраняет строку с `excluded=true`, без физического удаления или повторного включения.

Шаблон/генерация/перенос/отмена относятся к #30; отметки/закрытие — #31; создание нового гостя/разбор дублей — #32; допуск/контакты/история посещений — #33; интерфейс — #34, общая live-приёмка — #36. Эти функции не объявляются реализованными вместе с #29. До #31 roster отдаёт accepted unrecorded Attendance (`unmarked`, version0, null автор/время), без записи Attendance в БД. Optional contact/admission не выдаются этим срезом; их отсутствие не заменяется synthetic значениями. Известный Athlete(guest) можно включить, новый Person/Athlete этим API не создаётся.

## Объекты и версии

Все предметные ссылки составные `(tenant_id,id)`, RLS ENABLE/FORCE; runtime не получает DELETE/DDL/audit read/write. Venue/Discipline: ID, имя, archived, version. Group: имя, venue_id, discipline_id, archived, version и история Enrollment/GroupCoach. Одноимённые справочники допустимы. Account не требуется спортсмену. Тренер назначается по существующей активной ClubMembership с coach/assigned_sessions; Person/имя/телефон не выдают права.

Периоды UTC Z, полуоткрытые `[valid_from,valid_until)`; null until означает отсутствие конца. В одной группе интервалы одного Athlete/coach не пересекаются; разные группы/тренеры разрешены. Сокращение/исправление завершённого интервала, восстановление архива и массовая замена истории в этот срез не входят. End завершает открытый интервал, `until>from`; перевод — явный end старого и create нового Enrollment, без автоматического удаления других групп. Прошлые roster неизменны. Архив справочника/группы блокирует новые связи и занятия, сохраняет существующие записи/историю; end исторического интервала остаётся доступен.

Изменение Enrollment/GroupCoach повышает Group.version. `group_base_version` ручного создания защищает от изменения группы/подсказок после выбора менеджером. Manager вправе выбрать существующего активного спортсмена без Enrollment: его строка — visit (guest для существующего Athlete(guest)); действующее на starts_at Enrollment даёт regular. Trial передаётся отдельно. Первоначальный roster и coaches — явные массивы, пустые допустимы. Технические лимиты: не более100 строк и20 тренеров, тело по принятой политике до16KiB; это не утверждённый предел размеров клуба.

Session получает стабильный UUID, snapshot имён группы/зала, время UTC, state=planned, version1. Версия Session изменяется при roster/назначениях, не является Attendance.version. GroupCoach не выдаёт доступ к занятию: только текущий SessionCoach вместе с действующим club coach grant. PUT coaches явно задаёт весь текущий список ClubMembership ID с `base_version`; убранные назначения получают серверное время окончания и остаются в истории. Новые назначения разрешены только planned/in_progress; снятие для отзыва доступа разрешено также closed/cancelled. Неизменный список не повышает версию. Отзыв клубного coach немедленно прекращает доступ, даже при сохранённом SessionCoach; повторное назначение роли не меняет прежние интервалы.

## HTTP и повтор

Новые operationId/схемы/примеры — [OpenAPI](openapi/openapi.yaml), пути — [реестр](ENDPOINTS.md). Совместимые SessionJournal/TrainingSession/SessionPage/схемы add/exclude #16/#26 не расширяются скрытыми обязательными полями. История SessionCoach доступна manager через отдельный GET `/sessions/{session_id}/coaches`, без выдачи staff metadata тренеру.

Manager/administrator клуба, явный owner его сети или platform действуют только в разрешённом tenant. Coach-only: список текущих назначений за локальную дату Europe/Minsk, журнал конкретного текущего назначения и addKnown. Для неназначенного объекта404; административные операции403; чужой клуб403, чужой объект разрешённого клуба404. Проверка существования/принадлежности клиентских ссылок предшествует версиям и operation_id. Действующие права перечитываются после той же клубной блокировки, что у people/access #27; roster/assignments/state/archive/отзыв сериализуются.

Все новые команды: operation_id, при изменении base_version; строгие JSON поля, CSRF/exact HTTPS Origin/no-store/request_id, принятые нейтральные ошибки. Tenant/actor/version/автор назначения серверные. Никаких CORS, нового auth/scope, browser storage или прав по семье/телефону.

Идемпотентность по tenant/actor/operation_id, typed canonical hash включает API/kind/target/payload/base_version; результат, эффект, история и аудит атомарны. Повтор проверяет текущие права/ссылки/допустимость состояния прежде ответа. Тот же ключ/hash возвращает прежний безопасный результат без проверки старой base_version; другой hash409 OPERATION_ID_REUSED. Новая устаревшая команда409 ENTITY_VERSION_CONFLICT или SESSION_VERSION_CONFLICT. Терминальный конфликт версии сохраняется и повторяется; исправление требует нового operation_id и актуальной версии. Сохранённый результат не содержит контактов; архив/снятие coach не обходятся replay. В результатах не обещаются актуальные версии: после replay перечитать объект.

Каталоги: поиск по буквальной подстроке имени, state active/archived/all, UUID keyset, limit1–100(default30), не snapshot. Список Session: обязательная date в Europe/Minsk, limit1–100(default50), порядок starts_at/session_id, непрозрачный cursor связан с текущим входом/actor/tenant/date; каждая страница заново проверяет назначения. Истёкшая/другая сессия не принимает cursor. Точная дата/UUID/UTC Z валидируются. Полные production сроки OperationResult/retention/recovery epoch остаются #18/#24/#52; очистка ключей здесь не реализуется.

## Проверка реализации

Настоящий HTTPS HTTP→PostgreSQL: manager создаёт каталоги/группы/периоды/ручное занятие; несколько групп/тренеров; end/start перевод не меняет старый roster; GroupCoach не заменяет SessionCoach; coach видит только назначенное и после снятия получает404; coach add известного — visit без Enrollment, exclude/replace403; административное исключение сохраняет строку. Два клуба: чужие FK404/SQL отказ/RLS отсутствие контекста; старые версии409; два roster/coach изменения с одной версией — один эффект/один конфликт; конкурентные одинаковые operation_id — один результат/один аудит; отзыв роли против записи не пропускает потерявшего право.

HTTP/DB evidence отделяется от OpenAPI/AJV fixtures/Swagger/TS/chi.Walk. Closed/cancelled на границе29 проверяются отдельным synthetic setup в БД, без утверждения реализации close/cancel. Upgrade schema11→новая, повтор migrate/readiness/audit и неизменность прежних SQL обязательны. VPS/release/checkout/manifest/рабочие тома сохраняются; merge/зелёная CI не являются публикацией на judopride.tech.

Воспроизведение и разделение evidence: [training README](../docs/training/README.md), техническое решение — [ADR0015](../planning/adr/0015-training-groups-and-saved-roster.md). Shared people/training operation namespace проверяется под общей club lock; один ключ не создаёт эффект в обоих модулях. Replay временного добавления исключённого участника также возвращает ROSTER_EXCLUDED.

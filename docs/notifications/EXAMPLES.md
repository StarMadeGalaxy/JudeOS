# Синтетические примеры политики

Все обозначения вымышлены; даты не являются активацией. Это **документальные сценарии**, не доказательство исполнения Telegram, backend, RLS или worker. Проект решений — [APPROVAL](APPROVAL.md), тексты — [TEMPLATES](TEMPLATES.md).

## Один платёж, разные разрешения

Клуб «Синтетический Север», семья H: «Ребёнок А», «Ребёнок Б». Подтверждённое поступление R: **180,00 BYN**. Проект F1: A/2026-10 = **100,00**, Б/2026-10 = **60,00**, нераспределённый остаток **20,00**. Сверка в копейках: `18000 = 10000 + 6000 + 2000`. Семья H и сумма180 не передаются получателю.

- Person P-А: подтверждённый Telegram и GuardianLink только к А; явное разрешение финансовых полей А. Получает только `Ребёнок А: 100,00 BYN`.
- Person P-АБ: отдельно подтверждённый Telegram, связи и финансовая область обоих. Получает две строки100,00/60,00; сумма Receipt180/остаток20 не нужны даже ему.
- Person P-Н: входит в семью H, но нет проверенной связи/binding. Не получает сообщение или общий итог.
- Person P-Другой: действующий представитель А в другом клубе. Не получает данные «Синтетического Севера».

Один основной контакт не отменяет права второго подтверждённого представителя. У каждого отдельная проверка, проекция и исход; ошибка одного не раскрывает сведения другому.

Предложенный текст P-А:

```text
Распределённая поддержка · Синтетический Север · октябрь 2026
Ребёнок А: 100,00 BYN
Подтверждено.
Версия сводки 1.
```

**F2, исправление:** 20,00 перенесены с А на Б: A80,00/Б80,00/U20,00; `18000 = 8000 + 8000 + 2000`. P-А получает только80,00 и «Исправление распределения», не80 Б. **F3, подтверждённый возврат:**30,00 компенсируют распределение А: A50,00/Б80,00/U20,00, чистый денежный факт150,00; `18000 - 3000 = 5000 + 8000 + 2000`. P-А получает50,00 и «Подтверждённый возврат» после подтверждения семантики по #38; неизвестный банковский исход не сообщает возврат. Если компенсация А полная, разрешённый текущий результат0,00 показывается явно.

Если F1 не отправляли, ожидает только F2 или F3, а не три сообщения. Если F1 принят Telegram, F2 — явное исправление с новой версией. Если исход F1 unknown, перед F2/F3 требуется ручной разбор; новая версия не превращает повтор в безопасный автоматически. Уже отправленное после отзыва доступа не обещается удалить, но F2/F3 этому Person запрещены.

## Перенос и отмена

Синтетическое занятие S: группа «Учебная 1», исходное время `2030-01-14 17:00 Europe/Minsk`, зал «Учебный А». S1 переносит на18:00/залБ, S2 на19:00/залВ, S3 отменяет. Это пример будущих изменений с неизменным Session ID, не операция #29/#30.

```text
Изменение занятия · Синтетический Север
Учебная 1 · было: 14 января 2030, 17:00 (Europe/Minsk)
Перенесено: 14 января 2030, 19:00 (Europe/Minsk), Учебный В.
Версия изменения 2.
```

При отсутствии предыдущих отправок S1 устарел, отправляется S2; после S3 ожидающие переносы не отправляются, актуальна отмена. При уже принятом S2 отмена S3 — новое изменение. Person с двумя разрешёнными детьми в roster получает одну сводку без имён; Person без актуального права/roster не получает даже название группы.

## Матрица приёмки будущей реализации

| ID | Условие / действие | Ожидаемый результат проекта |
|---|---|---|
| N01 | /start или пересланная ссылка у постороннего | Только запрос проверки, ни данных ребёнка, ни права |
| N02 | Истёкший/повторный/отозванный токен | Нет доступа/привязки по токену; проверка #47 |
| N03 | Известный chat_id без подтверждённого Person | Не отправлять F/S |
| N04 | P-Н только в семье H | Не отправлять, семья не capability |
| N05 | P-А и P-АБ на F1 | Разные проекции100 и100/60, нигде180/20/чужие контакты |
| N06 | Представитель чужого клуба | Не отправлять, межклубного объединения нет |
| N07 | GuardianLink А отозван между подготовкой и попыткой | Перечитать; P-А не получает, P-АБ может получить только Б после новой проекции |
| N08 | Binding отозван, GuardianLink сохранён | Заблокировать канал, не выбирать иной chat_id автоматически |
| N09 | Область финансов неизвестна, расписная разрешена | F запрещён; S только по текущему roster и scope |
| N10 | Нет основного контакта | Не выбирать семейный fallback; ручная проверка контакта |
| N11 | Receipt подтверждён, но не распределён / импорт ещё не подтверждён | Нет F, финансовый разбор |
| N12 | Частичное F1 | Только подтверждённые100/60; остаток20 и рекомендация не раскрываются |
| N13 | F2/F3 / полная компенсация А | Новая явная версия/вид; текущие80/50/0; неизвестный возврат не объявляется подтверждённым |
| N14 | Меняется только Б; P-А имеет прежние суммы А | Не отправлять P-А сведения/обновление Б |
| N15 | F1 unknown; затем F2 | Нет автоматического повторения/обхода; manager разбирает исход |
| N16 | S1→S2→S3 до отправки | Только последняя актуальная отмена; не цепочка старых переносов |
| N17 | Два разрешённых ребёнка одного Person на S | Одна сводка без списка; разные Person проверяются отдельно |
| N18 | Roster/связь изменились до отправки S | Текущая проверка; потеря всей области запрещает S |
| N19 | S уже закончился / неизвестна актуальность | Старый перенос не посылать автоматически; ручной разбор |
| N20 | message_id / таймаут после возможного приёма | Приём не значит прочтение; unknown не значит failure; F только ручной разбор |
| N21 | Определённый отказ до приёма / blocked | Первый: ограниченный retry_after с guard; второй: остановка и проверенный контакт |
| N22 | Событие до гипотетической даты активации / исторический импорт | Нет исторического replay; сегодняшняя загрузка не маскирует историю |
| N23 | Изменение после активации во время pause | Событие сохранено будущим атомарным контрактом; внешней попытки нет |
| N24 | Pause→ручная связь→resume | Проверить ручной исход/права/версию, не автоматически повторять состоявшуюся связь |
| N25 | Событие на точной границе активации | Проверить серверную принятую activation_version, не время устройства; тест #49/#50 |
| N26 | Restore с отправленным сообщением/отозванной связью | Канал закрыт; независимая проверка прав и ручной разбор возможной доставки |
| N27 | Закрытие/исправление посещаемости, болезнь, изменение рекомендации | Ни F, ни S; поля не попадают в шаблоны |
| N28 | Повтор команды, outbox или expired lease | Не второй job; старый worker не завершает новый lease; доказать в #48 |

Граница активации в N22–25 гипотетическая `2030-01-01T00:00:00+03:00`, version1. Реестр ACTIVATION остаётся выключенным с неназначенной датой/версией. Эти примеры не содержат реальные Person/chat_id/телефоны/платежи.

## Проверки документа

Проверять точную арифметику F1/F2/F3, что P-А не содержит Б/семейный Receipt/остаток, один Session не раскрывает roster, ссылки/якоря/Markdown и сохранность общих файлов. Runtime-проверки N01–28 требуется выполнить в #47–#50 и при общей приёмке; чтение таблицы и арифметика их не заменяют.

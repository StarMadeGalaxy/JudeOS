## Блокер и проверки

CLI REST (`api.github.com/repos/...`) и GraphQL (`api.github.com/graphql`) получают `Forbidden`; Git fetch/push и GitHub-коннектор Issues/PR доступны. Коннектор отклоняет endpoints milestones и пользовательского Project как неподдерживаемые. Право записи в репозиторий подтверждено, но право редактировать Project, его поля/автоматизации и фактическое содержимое доски не проверены.

**Не применено:** семь milestones и их назначение, native blocked-by/sub-issues, добавление Issues в Project и его статусы/автоматизации. Текстовые ссылки зависимостей уже работают в Issues. Настройка подготовлена в [scripts/sync-github-planning.py](../scripts/sync-github-planning.py): по умолчанию чтение, `--validate` без сети, `--apply` для применения после проверки доступа. Статусы заполненного чужого поля не пересоздаются автоматически; assignees/сроки не меняются.

Проверены: публикация и отсутствие назначений всех 63 Issues через GitHub; наличие всех 120 ссылок зависимостей; ацикличность/полнота графа; покрытие S0–S5/P00–P12; Python-синтаксис и девять сценариев готовности/закрытия/отложенных задач/сохранения активного статуса; Markdown-ссылки/блоки и `git diff --check`. Read-only запуск скрипта подтверждает API-блокер до любых изменений. Применение API, доска/автоматизации и исполняемые проверки приложения не проверены; приложения/CI пока нет.

## Конкретный следующий шаг

Получить разрешённый доступ CLI к api.github.com и право редактировать Project #1 без передачи токенов в чат. Затем выполнить read-only preflight и `--apply` по ISSUE-BACKLOG.md, проверить read-back milestones, native dependencies/sub-issues, состав/статусы Project и его UI-автоматизации. Результаты — в #8; после подтверждения настройки обновить этот статус и закрыть #8.

Разработчики уже могут выбрать #16 (контракт), #17 (образцы) или #18 (условия реальных данных). После принятого контракта #16 доступны параллельно #19 (каркас) и #23 (прототип). Настройка Projects не является технической зависимостью синтетического каркаса; условия реального пилота и неподтверждённый iPay блокируют свои функции.
